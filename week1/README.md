## Причина ошибки

Исходный код использует иконочный шрифт Font Awesome Free 6.4.0.
JavaScript создаёт `<i class="..."></i>`, а сам символ задаётся CSS-псевдоэлементом
`::before`. В подключённом бесплатном CSS отсутствуют три использованных класса:

| Блюдо | Было | Стало |
|---|---|---|
| Ramen | `fas fa-bowl-hot` | `fas fa-bowl-food` |
| Pasta | `fas fa-pasta` | `fas fa-utensils` |
| Soup | `fas fa-bowl` | `fas fa-bowl-rice` |

При выборе этих блюд название меняется, но CSS не задаёт символ и иконка остаётся
пустой. В исходной странице ошибка воспроизведена для Soup: `::before.content`
равен `none`, ширина элемента — 0 пикселей. Для Tacos в той же сессии символ был
задан, ширина — 64 пикселя. При равномерном выборе проблема затрагивает 3 из 12
вариантов (25%), поэтому кажется непостоянной. Причина не в `Math.random()`.

Дополнительная зависимость исходника — внешний CDN, откуда загружаются CSS и
шрифты. Если эти ресурсы недоступны, могут исчезнуть и остальные иконки. Это
отдельный риск; воспроизведённая ошибка конкретных блюд вызвана отсутствующими
классами, а не установленным сбоем CDN.

## Что исправлено

1. Три отсутствующих класса заменены классами из фактического бесплатного CSS.
2. Вместо внешней ссылки подключены локальные `fontawesome.min.css` и `solid.min.css`.
3. Официальные шрифты WOFF2/TTF и лицензия сохранены в `assets/fontawesome/`.
   Относительные пути работают и в подпапке репозитория на GitHub Pages.
4. В `prompt.md` явно заданы проверка доступности классов, локальные зависимости,
   сохранение исходного приложения и критерии проверки.

Все изображения остаются символическими иконками, как в исходнике. Например,
для Pasta используются столовые приборы, для Soup — доступная иконка миски.
При загрузке приложения обращения к сторонним серверам за ресурсами не требуются.
Папку `assets` необходимо публиковать вместе с HTML.
